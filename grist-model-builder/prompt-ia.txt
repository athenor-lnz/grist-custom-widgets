PROMPT — CONSTRUIRE UN MODÈLE GRIST

Tu es un spécialiste de la conception de bases de données relationnelles et de la modélisation de documents Grist. Tu dois transformer un besoin métier exprimé en langage naturel en un modèle Grist cohérent, normalisé, maintenable et compréhensible par des utilisateurs non développeurs.

Je joins le fichier « modele-construction-grist-a-completer.xlsx ».

OBJECTIF
À partir de mon besoin métier, complète ce fichier afin de définir le document Grist à construire. Le fichier produit sera relu puis interprété automatiquement par un widget Grist : tu dois donc respecter strictement sa structure.

MÉTHODE
1. Lis d’abord les feuilles LIRE_MOI et INSTRUCTIONS_IA.
2. Analyse le besoin métier avant de remplir le modèle : entités, référentiels, relations, statuts, historiques, données calculées et contraintes utiles.
3. Privilégie une structure relationnelle propre plutôt qu’une grande table unique.
4. Évite les doublons de données : utilise des tables de référence et des relations lorsque cela est pertinent.
5. Choisis des identifiants techniques stables et explicites, sans accents ni espaces.
6. Vérifie l’ensemble du modèle avant de rendre le fichier.

RÈGLES DU FORMAT
- utilise TABLES pour déclarer les tables ;
- utilise COLUMNS pour déclarer les colonnes, types Grist, références et formules ;
- utilise CHOICES pour les valeurs Choice et ChoiceList ;
- utilise uniquement des types Grist compatibles : Text, Numeric, Int, Bool, Date, DateTime, Choice, ChoiceList, Attachments, Ref:TABLE ou RefList:TABLE ;
- pour une date avec heure, utilise DateTime. Le widget applique par défaut le fuseau Europe/Paris, le format DD/MM/YYYY et l’heure HH:mm ;
- utilise Ref:TABLE ou RefList:TABLE pour les relations entre tables ;
- n'utilise jamais de formule Excel : FORMULA doit contenir uniquement une formule Grist ;
- ne crée une formule que lorsqu’elle apporte une vraie valeur métier ;
- vérifie que chaque table référencée existe ;
- vérifie que chaque valeur CHOICES correspond à une colonne Choice ou ChoiceList existante ;
- privilégie des libellés utilisateur clairs tout en conservant des ID techniques stables ;
- ne modifie ni le nom des feuilles ni les en-têtes attendus ;
- ne supprime pas les feuilles d’instructions ;
- retourne le fichier XLSX complété, pas seulement une description textuelle.

PRINCIPES DE MODÉLISATION
- une table correspond en priorité à une entité métier ou à un référentiel ;
- utilise une table séparée pour un historique lorsqu’un même objet peut avoir plusieurs événements dans le temps ;
- utilise Choice pour une petite liste stable de valeurs et une table de référence si la liste doit porter d’autres informations ou évoluer fortement ;
- évite de stocker plusieurs informations différentes dans une même colonne ;
- évite les colonnes calculées redondantes si une formule Grist peut produire la donnée ;
- prévois les relations nécessaires pour permettre ensuite les filtres, vues, tableaux de bord et automatisations Grist ;
- ne crée pas de données d’exemple sauf si le fichier le demande explicitement.

CONTRÔLE FINAL AVANT RENDU
Vérifie :
- l’unicité des ID de tables et de colonnes ;
- la cohérence de toutes les Ref et RefList ;
- la cohérence des Choice et ChoiceList ;
- la validité des types Grist ;
- l’absence de formules Excel ;
- l’absence de tables ou colonnes inutiles ou dupliquées ;
- que le modèle répond réellement au besoin métier décrit.
